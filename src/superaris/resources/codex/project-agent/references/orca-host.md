# Orca terminal workbench

Use this entry when the prepared packet or current launch.json has `host: orca`.
The agent harness (Codex, Claude Code or AGY) is separate from the workbench host.
An older binding without a host field remains Herdr; do not migrate its team.

Read the project's existing startup instructions, recovery, role packet and
original task/memory files first. Product commands remain installed `superaris`
or the same interpreter's `python -m superaris`, including context, watch,
report, receiver and memory commands. Those commands target the original project
binding. For a new explicitly requested Orca project use `superaris start
/path/to/project --host orca`; inspect `--plan` before starting if needed.

Before operating the host, resolve the installed Orca CLI and read `orca --help`
and the relevant command's help for that installed version. Use the official
Orca CLI guidance at https://www.onorca.dev/docs/cli/overview and
https://www.onorca.dev/docs/cli/orchestration when necessary. Verify the actual
runtime, complete worktree/folder address, terminal handle, native process/session,
project cwd and owner against launch.json. Labels alone are insufficient. Never
use the focused tab as an implicit target or synthesize HERDR_ENV. A terminal
binding is not a Structured Chat handle; this integration uses terminal sessions.

SuperARIS owns this project's role assignments, registered receipt handles,
scientific acceptance and next steps. Orca provides its workbench and native
terminal delivery/receipts. Do not independently start Orca's native coordinator
or create a second task ledger for the same work. Use the existing product
watch/report/receiver chain and original owner to continue authorized work.
A native accepted-input receipt does not prove a turn started, the packet was
read, an artifact exists or the result passed acceptance. Preserve human drafts,
permission waits and unknown/expired delivery states; reconcile actual terminal
and receipt evidence before any resend. Changed owner/process/runtime identity
requires explicit handoff; do not replace the owner to keep receiving.

Preserve personal preferences, research wiki and task state in their existing
files. Re-read the current packet, recovery and originals after compact/restart.
Keep existing MCP routes, exclusive writer scopes, fresh independent reviewer
requirements, budgets and paused Goals. A persistent author session cannot
replace an independent reviewer. Workbench availability does not establish model
login, tool access or universal ARIS helper compatibility. UI closure and runtime
exit are distinct; inspect the bound receiver's actual status on recovery.
